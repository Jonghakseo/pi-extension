# excalidraw

`.excalidraw` 파일이 원본이다. 파일을 쓰면 열린 창에 바로 반영되고, 사용자가 창에서 고친 내용은 같은 파일에 저장된다.

```bash
EXCAL="node <이 스킬 디렉터리>/scripts/excal.mjs"
$EXCAL open <file> [--from-mermaid <file.mmd>]   # 창 열기(없으면 빈 파일 생성). 이미 열려 있으면 재사용. --from-mermaid는 파일 내용을 mermaid 결과로 교체
$EXCAL lint <file>        # JSON·참조·겹침·라벨 넘침 검사 (브라우저 불필요)
$EXCAL inspect <file>     # id/좌표/라벨/연결 요약. 큰 정식 파일을 통째로 읽지 말고 이걸 본다
$EXCAL snapshot <file> [-o out.png]  # 창에서 PNG를 내보내고 경로 출력 → read로 확인. 기본 경로는 파일마다 하나라 다시 찍으면 덮어쓴다
$EXCAL history <file>     # 외부 변경 직전 백업 목록 (최근 50개)
$EXCAL status | stop
$EXCAL build             # app/ 소스를 고친 뒤 재빌드
```

패키지에 빌드된 앱(`app/dist`)이 들어 있어 바로 열린다. `build`는 `app/` 소스를 고쳤을 때만 쓴다(첫 실행 시 의존성을 설치하므로 약 30초). 서버는 연결된 창 없이 30분이 지나면 스스로 꺼지고, 다음 명령에서 자동으로 다시 뜬다.

창은 Google Chrome 앱 창으로 열린다(Linux는 Chrome 또는 Chromium). `open`이 브라우저를 찾지 못하면 [references/setup.md](references/setup.md)의 최초 설치 방법을 사용자에게 안내한다. `lint`, `inspect`는 브라우저 없이 동작한다.

## 파일 위치

- 사용자가 경로를 말하지 않으면 현재 작업 디렉터리의 `./.diagrams/<kebab-case-주제>.excalidraw`에 만든다.
- 기존 파일을 고치라는 요청이면 그 파일을 쓴다. 같은 주제 파일이 `./.diagrams/`에 이미 있으면 새로 만들지 말고 수정한다.

## 새 다이어그램

1. 노드·연결·그룹 목록을 먼저 정하고, `references/style.md`에서 레이아웃 레시피를 고른다.
2. 작성 방식을 고른다.
   - 기본: 스켈레톤 JSON을 직접 쓴다(`references/skeleton.md`). 배치와 색을 통제할 수 있다.
   - 노드가 15개를 넘는 흐름, 시퀀스·클래스 다이어그램: Mermaid로 쓰고 `open --from-mermaid`로 가져온다. 자동 레이아웃이 붙는 대신 스타일 통제는 약하고, 긴 한글 라벨은 단어 중간에서 줄이 바뀔 수 있다. `.mmd`를 고쳐 다시 가져오면 같은 노드 id가 제자리에서 갱신된다. 가져온 뒤 파일을 직접 고쳤다면 다시 가져올 때 그 수정은 사라진다.
3. 파일 쓰기 도구로 `.excalidraw` 파일 작성 → `lint` → 오류를 고친 뒤 `open`.
4. `snapshot` → PNG를 `read`로 보고 겹침·잘린 라벨·어색한 화살표를 확인한다. 고칠 게 있으면 수정 후 한 번 더 확인한다(최대 2회).
5. 파일 경로와 한 줄 요약을 보고한다. 창은 이미 열려 있으니 URL은 붙이지 않아도 된다.

## 기존 다이어그램 수정

창이 열려 있으면 수정 즉시 반영되고, 무엇이 바뀌었는지 창에 토스트로 알린다. 사용자는 Cmd+Z로 파일 변경을 되돌릴 수 있다.

1. 수정 직전에 `inspect`로 현재 상태를 본다. 사용자가 창에서 옮기거나 고쳤을 수 있다.
2. 파일 편집 도구로 필요한 요소만 부분 수정한다. 새 다이어그램이 아니면 파일 전체를 다시 쓰지 않는다(사용자 편집이 사라진다). 요소 위치는 `rg -n '"id": "<id>"' <file>`로 찾는다.
3. 편집 규칙:
   - 이동·크기 변경: 도형의 `x`/`y`/`width`/`height`만 바꾼다. 라벨과 연결 화살표는 앱이 자동으로 따라 붙인다.
   - 라벨 변경·스타일 대수정: 그 요소를 스켈레톤으로 다시 쓴다. `version` 등 관리 필드를 빼고 `id`는 유지한 채 `label`을 넣으면, 이전 라벨은 앱이 지운다.
   - 추가: 배열 끝에 스켈레톤 요소를 붙인다. 기존 정식 요소 id에 `start`/`end`로 연결할 수 있다.
   - 삭제: 요소와 `containerId`가 그 요소인 텍스트, 연결된 화살표를 함께 뺀다.
4. `lint` → 필요하면 `snapshot`으로 확인한다.

## 주의

- 병합은 요소 단위다. 파일을 쓸 때 내용이 바뀌지 않은 요소는 사용자가 창에서 한 편집이 남고, 파일에서 바뀐 요소는 파일 값이 이긴다. 파일을 읽은 뒤 쓰기 전에 사용자가 같은 요소를 고쳤다면 그 편집은 파일 값으로 덮인다(Cmd+Z로 복구 가능). 그래서 수정 직전에 `inspect`하고, 바꿀 요소만 편집한다.
- 실수로 덮어썼다면 `history`에 나온 백업 파일을 `cp`로 되돌린다.
- `snapshot`은 창이 필요하다. 창이 없으면 자동으로 연다. 창이 최신 파일을 반영하지 못한 상태(파일 오류 등)면 이전 그림 대신 에러로 끝난다. 메시지를 보고 파일을 고친다.
- 텍스트 `width`/`height`는 창이 폰트 로딩 뒤 다시 재서 파일에 저장한다. 직접 계산해 넣지 않는다. 사용자가 창에서 글자 끝이 잘려 보인다고 하면 `snapshot`을 한 번 찍는다(내보내기 전에 창의 텍스트 크기를 다시 맞춘다). 그래도 잘리면 `inspect`로 텍스트 폭과 도형 폭을 비교하고, 앱 소스를 고친 경우라면 `build`가 빠졌는지 확인한다.
- 앱 동작(동기화, 정규화, 보안) 세부는 `references/sync-protocol.md`에 있다. 앱을 고칠 때만 읽는다.
